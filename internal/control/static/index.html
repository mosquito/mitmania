cached certs

Auto-refreshes every 2s. Per-process, not cluster-wide — each node in a fleet has its own.

Root CA

Install this on any client that needs to trust intercepted (mitm:true) connections — otherwise those clients see a certificate error. Not needed for clients that only ever hit mitm:false rules, since those splice TLS end-to-end with the origin's own real certificate.

Maintenance

Evicts every cached leaf certificate. Leaves are re-derived deterministically from clusterKey on demand, so this is always safe — it just costs the next intercepted connection per host a fresh signing pass instead of a cache hit. Useful after rotating the signing CA, or to force-drop a leaf you no longer want served.

Rules

Enter a client's source IP to view or replace its rule file. Changes take effect on that client's next connection — there's no separate reload step. Rules are evaluated top-down, first match wins; end with {"match": {}} for an explicit catch-all instead of relying on falling off the end (no match on a connection is a fail-closed 511). See the reference below for the full schema.

Default rules

Governs any client with no per-IP rule file above (including one just deleted) — there's always an answer here, so a client with no override never sees the bare fail-closed 511. Keyed by CIDR or sparse mask, e.g. "10.0.0.0/8" or "10.0.0.0/255.0.255.0" — the plain-prefix entries for each address family must together cover that whole family with no gaps, or the save is rejected naming the gap. A sparse mask is a pure override layered on top and doesn't count toward coverage.

Reference

Everything needed to hand-write a rule file, condensed from the actual schema — expand a section below.

Rule file shape

One rule file (per-IP or one bucket of the default table) is a single JSON object:

{
  "uuid": "<uuid4, or omit and one is minted for you>",
  "auth": { "http_proxy": { ... } },
  "http": [
    { "match": { ... }, "mitm": true, "request": [...], "response": [...] }
  ],
  "egress": [
    { "cidr": "10.0.0.0/8", "action": "deny" }
  ]
}
FieldMeaning
uuidStable client identity sent to outcall brokers. Optional — omit it and one is minted and persisted the first time this file is looked up.
authOptional. Proxy-Authorization credentials this client must present. See "Auth" below.
httpOrdered list of rules, evaluated top-down, first match wins. Required (may be empty).
egressOptional. Omitted entirely = inherit the node's default egress list. Present-but-empty ([]) matches nothing, i.e. denies every destination — not the same as omitting the key.
Match fields (host/port/proto/path/method/header)

Every field is optional; an omitted or empty field means "match anything" (*). Each value is either a glob (*/?) or a regex prefixed re:, e.g. "re:^api\\.".

FieldPhaseMatches against
hostconnectionCONNECT/SNI/absolute-URI authority host
portconnectiondestination port
protoconnection"http" or "https"

headermessagea map of header name → value pattern, every entry must match

Connection-phase fields decide MITM-or-splice before any bytes are decrypted; message-phase fields (path/method/header) need decrypted content and therefore force interception — a rule combining them with "mitm": false is rejected at load, not silently ignored.

connection: {accept: false}

Phase 1 (connection checks), evaluated before mitm (phase 2, rule matching) applies at all. {"accept": false} rejects the connection outright — no dial, no TLS termination, no certificate ever presented, so the client needs no CA trust. This is the only way to reject purely by host/port/proto (e.g. SNI): mitm: true + a request-phase block/raise action can also reject, but only after terminating TLS to reach the message phase.

accept is required when connection is present. accept: true is valid and is just the already-default phase-1 behavior stated explicitly — a no-op that composes freely with mitm/message fields/actions (useful as a self-documenting exception ahead of a broader accept: false rule). accept: false cannot be combined with mitm, message-phase match fields, or request/response actions — rejected at load, not silently ignored.

mitm: true / false

Default is true when the key is omitted. false is a raw, end-to-end encrypted splice — mitmania relays bytes without ever seeing plaintext, so it can authorize only what a CONNECT/SNI/ absolute-URI already reveals (host, port, proto). It cannot see or act on method, path, headers, or body, and none of request/response/message-phase match fields may be set on that rule. true terminates TLS under the signing CA (see "Root CA" — clients need it installed), decrypts, evaluates the message-phase pass, and can run request/ response actions.

Egress rules

egress[] constrains which resolved destination address a connection may reach — independent of the host-based http[] match, and enforced for both mitm:true and mitm:false connections alike, after DNS resolution, before dialing. 

{ "cidr": "10.0.0.0/8", "port": "1-1024", "proto": "tcp", "action": "deny" }
FieldMeaning
cidrRequired. Destination prefix, v4 or v6.
portOptional. Exact number, "lo-hi" range, or omitted/"*" for any.
protoOptional. Omitted matches any.
actionRequired. "allow" or "deny".

First match wins, same ordering discipline as http[]. A typical list denies loopback/RFC1918/link-local first (the SSRF-guard ranges), then allows everything else — those trailing allow entries are load-bearing, not decorative, since no-match is itself a denial.

Auth (Proxy-Authorization)

Gates the explicit proxy itself, independent of which rule file ends up selected — it never chooses rules, only attributes/admits the connection.

"auth": {
  "http_proxy": {
    "required": true,
    "realm": "mitmania",
    "basic": [{ "user": "alice", "hash": "$argon2id$..." }],
    "bearer": [{ "id": "ci-token", "hash": "sha256:<hex>" }],
    "broker": { "url": "https://broker.internal/auth" }
  }
}

Passwords are never stored in plaintext: basic[].hash is a canonical $argon2id$... PHC string, bearer[].hash is sha256:<hex> of the presented token. broker delegates the check to an outcall instead (exactly one of socket/url, like webhook).

Default rules (rules/default) keys

Each key is an address and a mask, addr/mask. The mask is either a decimal prefix length (/8) or a literal mask in the family's own notation (/255.0.255.0) — the latter lets bits identifying a client be non-contiguous, e.g. two fixed bytes carved out of a wider block handed out per network segment.

0.0.0.0/0 and ::/0 are the minimum viable table (one bucket per family, matching everything in it). Add more specific plain-prefix entries to segment policy by subnet; add a sparse-mask entry to carve out a slice of an existing block without it counting toward the coverage requirement.
